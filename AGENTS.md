# AGENTS.md

figpress-apps (formerly figkit; part of the figpress family) is a toolbox for webapps that are the
interactive counterparts of scientific papers: a Python package that exports data, builds sites and
runs JS tests, carrying a browser library of plain ES modules. Read `.specify/memory/constitution.md` first; it overrides everything here.

## How work is done here

This repo uses [Spec Kit](https://github.com/github/spec-kit) v1.1.3 (`.specify/`, commands as
`.claude/skills/speckit-*`). A feature goes `/speckit-specify` → `/speckit-plan` → `/speckit-tasks`
→ `/speckit-implement`, in `specs/NNN-name/`. Small fixes that change no public API go straight to
a pull request.

## Layout

```
src/figpress_apps/            Python: data.py (export/load), build.py (build, inline_modules, checks),
                       serve.py, cli.py (build/serve/test), anywidget.py (notebook Widget)
src/figpress_apps/js/         browser library (package data, vendored into built sites):
                       index.js model.js npy.js data.js geom.js stage.js globe.js skypanel.js index.css
src/figpress_apps/node/       Node-only test tooling for `figpress-apps test` (resolve hooks); never shipped to browsers
examples/globe/        the globe example (also the gallery entry and acceptance test); prototype/ is
                       the page it replaced, kept for reference
examples/gallery.py    the gallery's index page
skills/figpress-apps/         skill: building a webapp (references/, assets/template/)
skills/figpress-apps-upgrade/ skill: moving a webapp to a newer figpress-apps tag
tests/                 pytest (test_smoke.py: browser tests, marker `smoke`); make_fixtures.py
js-tests/              node --test (fixtures generated by tests/make_fixtures.py)
package.json           test-only: lets Node resolve figpress-apps/… inside this repo (no dependencies)
CHANGELOG.md           every release; migration notes for breaking changes (shipped in the wheel)
```

## Conventions that are easy to break

- JS modules import each other only by bare specifiers (`figpress-apps/model.js`, `app/science.js`), never
  `./x.js`, and never use `import.meta.url` (except Node tooling in `src/figpress_apps/node/`).
  `figpress-apps build` rejects violations; it also checks figpress-apps' own modules.
- No DOM access at module top level. Pure kernels (shading, autoscale, geometry) are exported
  separately from `mount` so Node can test them.
- Components export `mount(el, model, opts) → dispose`; model values are replaced, never mutated.
- Science-specific code stays in apps (`science.js`), never in figpress-apps.
- Code enters figpress-apps only when a real app needs it.

## Testing

```bash
uv run pytest                                                  # not the smoke tests
uv run python tests/make_fixtures.py && node --test js-tests/*.test.js
uv run pytest -m smoke --browser chromium --browser webkit     # Firefox runs in CI
```

## Releasing

Versions are dates. A release is tagged `vYYYY.MM.DD` (`__version__ = "YYYY.MM.DD"`); a bug-fix
release of it is `vYYYY.MM.DD.N`. Papers pin an exact release, so every bug fix is backported to
every released version that has the bug, and each gets its own `.N` — a pinned paper can take a fix
without anything newer. (`v0.1.0` and `v0.2.0`, with branches `versions/v0.1.x` and
`versions/v0.2.x`, predate dates; a fix for them is `0.1.N` / `0.2.N` on those branches.)

**A release, `vYYYY.MM.DD`, from `main`:**

1. In a pull request: set `__version__` to the date, and turn `## Unreleased` in `CHANGELOG.md`
   into `## YYYY.MM.DD — YYYY-MM-DD`. Every breaking change needs a migration note
   (**What changed**, **Find**, **Edit**); public-API changes update both skills.
2. Squash-merge it (the only method `main` allows), then tag the merge commit:
   `git tag -a vYYYY.MM.DD <sha> -m "figpress-apps YYYY.MM.DD" && git push origin vYYYY.MM.DD`.
   No branch yet: `versions/vYYYY.MM.DD.x` is created the first time a fix needs it.
3. The tag runs `release.yml`, which checks it equals `v` + `__version__`, tests, builds and
   publishes to PyPI with trusted publishing (environment `pypi`; no token stored).
4. `gh release create vYYYY.MM.DD --verify-tag` with the changelog section as notes; `gallery.yml`
   deploys the examples to Pages.

**A bug fix, backported everywhere it applies:**

1. Fix it on `main` first (pull request with a test that fails before the fix), and add the fix
   under `## Unreleased` → **Fixed**.
2. List the released versions that have the bug: every `v*` tag whose code contains it (check with
   the new test, or by reading the code at the tag).
3. For each, oldest to newest: create `versions/<tag>.x` from the tag if it doesn't exist
   (`git branch versions/<tag>.x <tag> && git push origin versions/<tag>.x`), open a pull request
   into it that cherry-picks the fix (`git cherry-pick -x <sha>`), sets `__version__` to the next
   `.N` (or `0.Y.N` on the old semver branches) and adds a `## <version> — <date>` changelog section
   with only that fix. Merge after CI passes, tag `v<version>` on the merged commit, push, and
   `gh release create`.
4. Record the bug-fix releases in `main`'s `CHANGELOG.md` too, so its history is complete.

Bug-fix releases never contain breaking changes or new features. A fix that cannot apply cleanly to an
old version is adapted in that version's pull request, or skipped there with the reason in the
pull request and the changelog.

## Pull-request previews

Every pull request gets a live preview of the gallery on Cloudflare Pages (project `figpress-apps`,
branch `pr-<number>`), posted as a sticky comment by the `preview` job in `tests.yml`. It needs the
repository secrets `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` and skips without them. The
one check to require in branch protection is **CI Pass**.
